# Отчет: поиск блюда на сайте

## Вывод

Функция реализуема. В текущем приложении нет сетевого слоя; это iOS-приложение на SwiftUI/SwiftData, поэтому запросы можно добавить через `URLSession`. Уже существующий AI-сценарий умеет открывать внешние приложения и сайты, что также позволяет сделать простой вариант без интеграции API.

До реализации нужно выбрать сайт и ожидаемое поведение: открывать страницу поиска в браузере либо показывать результаты внутри приложения и подставлять выбранное блюдо.

## Варианты

### 1. Открывать поиск на выбранном сайте — низкая сложность

Приложение открывает Safari со сформированным запросом. Это не требует API-ключа и не зависит от формата данных сайта. Пользователь сам выбирает результат и переносит значения в приложение. Приложение не сможет надежно прочитать страницу и автоматически заполнить калории.

### 2. Показывать результаты в приложении через API — средняя сложность

- **USDA FoodData Central** подходит для поиска общих продуктов и пищевой ценности. API предоставляет поиск продуктов и получение подробностей, но требует ключ data.gov в каждом запросе. Ключ, встроенный в мобильное приложение, можно извлечь, поэтому для публичного релиза нужен серверный прокси или иной способ безопасно выдавать ключ. Данные USDA находятся в общественном достоянии (CC0).  
  Документация: https://fdc.nal.usda.gov/api-guide/
- **Open Food Facts API v3** подходит прежде всего для упакованных товаров и их маркировки. База пополняется сообществом, данные могут быть неполными или неточными. Документация ограничивает поиск 10 запросами в минуту на IP, поэтому нельзя отправлять запрос на каждый символ; для новых интеграций рекомендована версия v3.  
  Документация: https://openfoodfacts.github.io/openfoodfacts-server/api/

Для обоих API потребуется обработать отсутствие результатов, сетевые ошибки, ограничения частоты запросов и отображать источник данных. Выбранный результат можно подставлять в название и ккал/100 г, оставляя подтверждение пользователю.

## Рекомендация

Если нужен быстрый и надежный первый вариант без серверной инфраструктуры — открывать поиск на конкретном сайте в браузере. Если нужны результаты и автозаполнение внутри приложения, для общих блюд предпочтителен USDA через небольшой серверный прокси; для товаров с упаковкой — Open Food Facts API v3 с ограничением частоты запросов.
